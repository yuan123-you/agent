> 项目名称：AI Mall 智能电商平台（内含 AI Agent）
> 文档版本：v2.0
> 最后更新：2026-08-20
> 文档状态：待评审
> 变更说明：v2.0 由「智能售后服务平台」调整为「智能电商平台」，取消客服主管角色，新增 AI 高亮链接跳转能力，并整体精简为聚焦主要功能的版本（砍掉多租户、SLA、质检、复杂看板）。

## 1. 项目背景与目标

### 1.1 项目背景

传统电商平台存在三大体验痛点：

1. **找货难**：商品海量，用户只能靠搜索框关键词 + 逐页翻列表，无法用自然语言表达真实需求（"想给爸妈买部字体大、电池耐用的手机，2000 以内"）。
2. **信息散**：商品参数、优惠活动、售后政策分散在详情页、FAQ、客服话术中，用户反复跳转比对。
3. **人工客服贵**：查订单、查物流、退换货咨询等标准问题占用大量人工，响应慢、成本高。

随着大模型 + RAG + Agent 技术成熟，**AI 导购助手**可以直接理解需求、检索商品、查询订单，并把结果以"可点击的高亮链接"嵌在回答里，实现「对话即购物」。

### 1.2 一句话定位

**AI 购物助手驱动的智能电商平台**——用户用自然语言对话，AI 帮你搜商品、比价、查订单、答疑，回答中的商品/订单以**高亮文字链接**呈现，点击直达对应页面；必要时无缝转人工客服。

### 1.3 典型场景

场景一：AI 导购

```
用户："推荐一款 3000 以内拍照好的手机"
AI（内部流程）：
  意图识别 → 商品咨询/推荐
  ↓
  调用商品检索工具（价格 ≤3000、卖点=拍照）
  ↓
  结合商品知识库 RAG（评测、参数亮点）
  ↓
  生成推荐回答（流式输出，商品名为高亮链接）
用户看到的回答：
  "为您找到 3 款符合条件的手机：
   1. [星耀 X5 Pro](mall://product/1001) —— 5000 万像素主摄…点击商品名可查看详情"
用户点击"星耀 X5 Pro" → 跳转商品详情页
```

场景二：订单服务

```
用户："我上次的订单到哪了？"
AI：调用订单查询工具（仅本人订单）→ 流式回答
   "您的订单 SO202608180012（含 [星耀 X5 Pro](mall://product/1001)）已发货，
    预计明天送达，[点击查看订单详情](mall://order/5001)"
用户点击 → 跳转订单详情页
```

场景三：转人工

```
用户："退货怎么弄？我要投诉"（AI 判断无法自助解决 / 用户明确要求）
AI：调用转人工工具 → 会话进入人工队列
客服在工作台接入 → 携带 AI 会话摘要 → 人机无缝续聊
```

### 1.4 项目目标

| 目标类型 | 目标描述 | 度量指标 |
|---------|---------|---------|
| 业务目标 | AI 独立完成导购与订单咨询 | AI 独立解决率 ≥ 70% |
| 业务目标 | 提升找货效率 | 从"搜索+浏览"到"对话直达商品"≤ 2 轮对话 |
| 业务目标 | 降低人工客服压力 | 人工接待量下降 ≥ 50% |
| 技术目标 | 建成电商 Agent + RAG 架构 | 三层隔离架构落地，AI 服务可水平扩展 |
| 技术目标 | 链接跳转体验 | AI 回答内高亮链接点击跳转成功率 100% |
| 体验目标 | 响应速度 | SSE 首 token P95 < 3 秒 |

### 1.5 范围界定

本项目是**以 AI Agent 为核心的智能电商平台**：电商侧实现商品浏览、下单（模拟支付）、订单管理的最小闭环；不做真实支付、营销系统、库存供应链、购物车（P2）。

## 2. 目标用户画像

> 角色体系共 4 类：买家（CUSTOMER）、卖家（MERCHANT）、人工客服（AGENT）、管理员（ADMIN）。`MERCHANT` 是技术契约字面量，面向用户始终显示“卖家”；**无 MANAGER 角色**。

### 2.1 买家（CUSTOMER，C 端）

| 属性 | 描述 |
|------|------|
| 身份 | 平台消费者 |
| 设备 | 手机/PC 浏览器 |
| 核心诉求 | 用自然语言找商品、比价；快速查订单/物流；售后答疑；不想打字翻页 |
| 使用特征 | 非技术背景，需求表达口语化（"送妈妈的"、"性价比高的"） |
| 敏感点 | 推荐不准、链接点不动、AI 答非所问 |

### 2.2 卖家（MERCHANT，卖家端）

| 属性 | 描述 |
|------|------|
| 身份 | 在平台注册并经营店铺的卖家；注册时必须填写店铺名称 |
| 设备 | 卖家端 Web |
| 核心诉求 | 管理自己的商品与买家评价 |
| 权限边界 | 仅能创建、编辑、上下架、删除自己的商品；不能访问管理员后台 |

### 2.3 人工客服（AGENT，B 端）

| 属性 | 描述 |
|------|------|
| 身份 | 平台客服专员 |
| 设备 | 极简工作台（Web） |
| 核心诉求 | 只处理 AI 解决不了的问题；接管时能看到 AI 会话摘要；快速查用户订单 |
| 敏感点 | 接管后信息断层、重复提问 |

### 2.4 管理员（ADMIN，B 端）

| 属性 | 描述 |
|------|------|
| 身份 | 平台运营/管理员 |
| 设备 | 管理后台（Web） |
| 核心诉求 | 新建商品、商品上下架；维护商品知识库（FAQ/介绍）；处理订单（发货）；按看板查看运营和 AI 使用情况；管理用户状态与客服账号 |
| 敏感点 | 知识库陈旧导致 AI 答错、商品信息错价 |

| W-02 | 待接入列表 + 接管会话 | P1 | 展示 AI 摘要，抢占式接管防双接 |
| W-03 | 人工回复 | P1 | 普通消息接口，非 SSE |
| W-04 | 快捷回复 | P2 | 常用话术 |

### 3.5 管理后台功能（ADMIN）

| 编号 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| M-01 | 商品管理 | P0 | 商品列表、新建和上下架；管理员**不编辑商品**，商品编辑保留给卖家端 |
| M-02 | 知识库管理 | P0 | 文档上传（PDF/MD/TXT）→ 自动分割向量化；启用/停用 |
| M-03 | 订单管理 | P0 | 订单列表、发货操作（更新物流状态） |
| M-04 | 用户管理 | P1 | “买家 / 卖家 / 客服”三标签；不显示管理员；仅启用/禁用，管理员仅能创建客服、无角色转换 |
| M-05 | 数据看板 | P1 | `/admin/dashboard`；以 `Asia/Shanghai` 今日窗口汇总运营、订单、会话和 AI 指标 |
| M-06 | 使用统计 | P1 | 极简统计页：会话量、AI 消息量、热门问题 TOP N |

### 3.6 明确不做（Out of Scope）

- 真实支付/退款资金流（模拟支付）
- 购物车、优惠券、营销活动（P2 或不做）
- 多租户 SaaS 化（单平台运营）
- SLA 管理、客服质检、复杂数据看板（已随复杂度裁剪移除）
- AI 模型训练/微调（仅 RAG + Prompt 工程）
- 移动端原生 App（响应式 Web 覆盖）

## 4. 用户使用流程图

### 4.1 核心流程：对话推荐 → 链接跳转 → 下单

```
┌────────┐   ┌────────┐   ┌────────────┐   ┌────────────┐
│ 买家    │   │ 前端    │   │ SpringBoot │   │ Python AI   │
│(浏览器) │   │ Vue3    │   │  后端      │   │  推理服务    │
└───┬────┘   └───┬────┘   └─────┬──────┘   └─────┬──────┘
    │ 1."推荐3000以内的拍照手机" │             │            │
    │──────────>│ 2.POST /chat/messages(SSE) │            │
    │           │────────────>│ 3.鉴权/限流/落库用户消息     │
    │           │             │ 4.WebClient转发 ──────────>│ 5.意图:商品推荐
    │           │             │             │   5.1 product_search工具
    │           │             │<──工具回调────│      ↓
    │           │             │ 6.返回商品列表│   5.2 kb_search(评测RAG)
    │           │             │─────────────>│      ↓
    │           │ 7.SSE流式返回│             │   5.3 生成回答(含链接语法)
    │           │<────────────│ <───────────│
    │ 8.逐token渲染,商品名高亮 │             │
    │<──────────│             │             │
    │ 9.点击"星耀X5 Pro"高亮链接            │
    │──────────>│ 10.router.push(/products/1001)        │
    │ 11.浏览详情,点击[立即购买]→模拟支付→订单│
```

### 4.2 AI 查订单流程

```
买家："我的订单到哪了"
→ AI 意图:订单查询 → order_query 工具(回调后端,仅本人订单)
→ 流式回答:"订单 SO…12 已发货…"（订单号为高亮链接 mall://order/5001）
→ 点击 → /orders/5001 订单详情页
```

### 4.3 转人工流程（P1，极简）

```
买家明确要求转人工 / AI连续2轮无法解决
→ AI 调用 escalate 工具 → 会话状态 PENDING_HUMAN
→ 客服工作台待接入列表出现（含AI摘要）
→ 客服"接入"（抢占式，防双客服同接）→ 会话 SERVICING
→ 客服与买家在同一会话流沟通（普通消息接口）
→ "结束服务" → 会话关闭 → 触发满意度评价
```

### 4.4 知识库维护流程

```
管理员上传商品FAQ/介绍文档(PDF/MD/TXT)
→ 后端存储文件 → 调 AI 服务文档摄取
→ 解析→分割→向量化→写入 Milvus → 状态回写(处理中→已生效)
→ 生效后 AI 对话即可检索引用
```

## 5. 非功能需求

### 5.1 性能

| 指标 | 目标值 | 说明 |
|------|--------|------|
| SSE 首字节时间（首 token） | P95 < 3s | 请求到前端首个 token |
| 普通 REST 接口 | P95 < 300ms | 商品/订单查询 |
| RAG 检索延迟 | P95 < 800ms | Milvus 检索 + 重排 |
| 并发会话 | 单 AI 实例 ≥ 100 并发 SSE | 无状态可水平扩展 |
| 会话历史加载 | < 500ms | 最近 20 条分页 |

### 5.2 安全

| 需求 | 说明 |
|------|------|
| 认证 | JWT（Access 2h + Refresh 7d），后端统一校验 |
| 授权 | 3 角色 RBAC；行级校验（买家只能查自己的订单/会话） |
| 密钥管理 | LLM API Key 等全部环境变量，禁止硬编码、禁止下发前端 |
| 服务间安全 | 后端 ↔ AI 服务内网隔离 + 内部服务令牌（X-Internal-Token） |
| 越权防护 | AI 工具身份由服务端注入（不信任模型生成的 userId） |
| 输入防护 | 参数校验、SQL 预编译、XSS 转义、Prompt 注入基础防护 |
| 链接安全 | AI 生成的内联链接仅限白名单 scheme（mall://），前端禁止渲染外链跳转 |

### 5.3 可用性

| 需求 | 说明 |
|------|------|
| 降级 | LLM 不可用 → 降级话术 + 引导转人工/自主浏览商品列表 |
| 熔断限流 | Resilience4j 熔断；每用户对话限流（20 次/分钟） |
| 数据可靠 | AI 回复（含工具调用与链接原文）落库，刷新不丢失 |
| 部署 | Docker Compose 一键编排，AI 服务可加副本扩展 |

### 5.4 可观测性

- traceId 贯穿前端→后端→AI 服务；
- AI 消息记录 token 用量与耗时（message 表），支撑成本分析；
- 健康检查：后端 `/actuator/health`、AI 服务 `/health`。

## 6. 验收标准

### 6.1 功能验收

| 编号 | 验收项 | 通过标准 |
|------|--------|---------|
| F-01 | AI 流式对话 | 逐 token 渲染；工具调用过程可见；五类事件正确区分 |
| F-02 | 高亮链接跳转 | AI 推荐回答中商品名为高亮文字，点击跳转到正确商品详情页；订单链接同理 |
| F-03 | 商品推荐准确性 | "3000 以内拍照手机" 返回商品均满足价格约束，且来自商品库真实数据（不编造） |
| F-04 | RAG 有效性 | 询问知识库中的售后政策/商品 FAQ，答案正确并标注来源 |
| F-05 | 订单闭环 | 详情页下单→模拟支付→订单列表可见→管理员发货→状态更新 |
| F-06 | AI 查订单 | 只返回本人订单；回答内订单号为可跳转链接 |
| F-07 | AI 下单（P1） | 对话确认后创建订单，重复确认不重复下单（幂等） |
| F-08 | 知识库全流程 | 上传→已生效→对话可检索；停用后不再命中 |
| F-09 | 转人工（P1） | 触发后工作台可见会话+摘要，接管后消息互通 |
| F-10 | 权限隔离 | CUSTOMER 无法访问管理接口；AGENT 仅工作台；ADMIN 全部 |

### 6.2 非功能验收

| 编号 | 验收项 | 通过标准 |
|------|--------|---------|
| N-01 | 性能 | 100 并发 SSE，首 token P95 < 3s，无连接泄漏 |
| N-02 | 容错 | 停 AI 服务 → 后端快速熔断，前端收 error 事件与友好提示 |
| N-03 | 密钥安全 | 仓库 grep 无明文 Key；前端网络面板无 LLM 请求 |
| N-04 | 部署 | `docker compose up -d` 一键拉起全部服务 |
| N-05 | 越权 | 用买家 A 令牌查买家 B 订单/会话 → 403 |
| N-06 | 链接安全 | AI 回答中注入的外部 URL 不被渲染为可点击跳转（仅白名单 scheme） |

### 6.3 交付物清单

- 前端、后端、AI 服务三套可运行源码 + Docker Compose 编排
- 数据库初始化 SQL + 种子数据（管理员账号 + 示例商品 + 示例 FAQ 文档）
- 8 份设计文档 + README 快速启动说明
