# 商城跨页面/API 一致性排查报告 — 2026-10-26

## 结论与验证边界

这不是仅隐藏控制台报错的修改。排查从“已评价订单返回后重复弹评价”扩展到了页面与API契约、对象归属、重复请求、数据库事务、库存、优惠券、默认地址、异步知识库回调和SSE生命周期。

- 本地提取了 132 条标准 HTTP 映射，定位清单见 `2026-10-26-api-inventory.md`；**清单不等于每条接口均经过真实环境动态验证**。
- 对确认的问题先运行失败回归，再最小修复。数据库并发测试使用真实 MyBatis SQL、Spring 事务、独立连接和 H2 MySQL 模式；不把 Mockito 当成数据库原子性证明。
- 未连接生产数据库、未修改生产记录、未执行数据去重/修复、未部署或推送代码。未使用生产账号进行攻击性探测。
- H2、内存 Redis 替身和模拟前端 API 不能证明生产 MySQL/InnoDB、Redis、Milvus、多实例和反向代理的全部行为；仍需预发布联调。
- 工作区存在本轮之外的并行 AI/聊天/导航变更，保持原样，没有回滚或把它们计入本轮修复。

## 1. 直接事故：评价入口和409

实际有多个叠加根因，而不是一个简单的缓存问题：

1. `MyOrdersView` 每次列表加载都重新读取 `reviewOrderId` 并打开弹窗，导航意图未消费。
2. 列表和详情只按 `DELIVERED` 提供评价入口，没有持久化评价状态。
3. 提交评价的 `catch` 与成功分支一样提示成功并关闭弹窗，掩盖了服务端409。
4. 多商品订单固定取第一件，缺失商品时回退到 `productId=1`。
5. 同时切换筛选/SSE刷新时，旧请求可能覆盖新列表，且旧 `loading` 阻止新请求。

本轮改为：后端返回每个明细的 `orderItemId / reviewed / canReview`；前端消费一次URL意图并移除该参数；只允许选择实际可评价明细；提交中防重复；失败保留草稿且不报成功；持久化成功后同步当前商品在所有已加载订单中的状态；请求代次隔离旧响应；详情监听路由复用。

**业务规则未擅改：**仍然是一用户一商品一条有效评价，不是每个订单均可再评价一次。重复提交保持409冲突契约，但不能再次产生评价记录。若要改为“每笔购买可评价”，需要先明确规则，再安排历史数据迁移和唯一性约束。

## 4. 待决策与仍需验证的风险

1. **AI action跨动作幂等规则。**缓存粒度为“会话+商品”，数据库action关联又有唯一约束。同一会话再次购买同款究竟是新购买还是旧请求重试，不能在没确认业务规则时擅自改变。当前按同action的重复确认与事务回滚保障处理。
2. **收藏toggle本身不是目标状态幂等API。**重试可再次翻转状态。要获得网络重试幂等，需要明确设置/取消目标状态的接口，不能只靠禁止重复点击。
3. **历史脏数据未自动清理。**历史重复评价、孤儿收藏/历史、已存在的多个默认地址、券核销引用等，需要在生产只读核对和备份后再制定迁移；本轮不会猜测真实数据或删除记录。
4. **真实环境并发。**需要独立预发布MySQL/Redis/Milvus验证RR快照、锁顺序、死锁重试、事务回滚、服务重启和多实例，以及浏览器多标签页/断网恢复。
5. **跨系统原子性与首次播种。**数据库与Milvus不在同一事务，清理后迟到旧向量仍可能残留；当前关系版本校验使其不可见，但并非完全无残留。多实例首次创建同标题seed文档尚无唯一claim，需要另行处理。
6. **账号禁用不等于撤销所有已建立流。**本轮保护后续认证请求；已建立的SSE或进行中的操作需另定主动断开/撤销政策。
7. **演示行为和宣传数据。**现有模拟支付/发货、固定物流、保障、销量/划线价不能直接当成真实交易能力。需要明确演示与正式业务的上线边界。
8. **数据库唯一约束。**评价的原子保障依赖所有新增写入路径遵守用户行锁协议。没有为历史重复数据强行增加唯一索引；若需数据库层最终唯一约束，必须先清点存量并设计不丢数据迁移。

## 6. 发布注意事项

- 本轮未发布，线上现象不会因为本地改完自动消失。
- 新评价状态需要后端和前端配套发布；旧前端仍可能重复展示入口，但后端应继续阻止重复落库。
- 知识库回调的docVersion需要Java后端和Python AI worker协同发布。旧在途worker缺失版本会被拒绝，部署前应清点/排空任务并重建必要文档，不能为兼容旧任务重新放开无版本写入。
- 所有执行向量清理的AI worker必须升级并重启；旧代码实例仍可能发出危险的“不等于当前任务版本”过滤器。
- 发布后先用两个独立买家/客服账号验证归属，再跑评价返回、并发取消/支付、SKU库存、券释放、停用文档迟到回调等小规模可回滚检查，不对生产做无边界压力测试。
