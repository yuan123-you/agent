## 1. Docker Compose 编排方案

### 1.1 服务拓扑

```
docker-compose.yml 编排 7 个服务：

┌─────────────── ai-net (bridge 内部网络) ──────────────────────┐
│                                                                │
│  frontend(nginx:80) ←仅后端可被外部访问                        │
│    │ proxy /api → backend:8080                                 │
│    ▼                                                           │
│  backend:8080 (对外映射 8080)                                   │
│    │          │              │                                 │
│    ▼          ▼              ▼                                 │
│  mysql:3306  redis:6379    ai-service:8000 (不对外映射!)        │
│  (可映射宿主机)              │        │                          │
│                            ▼        ▼                          │
│                        milvus:19530  etcd+minio (milvus依赖)    │
│  LLM API(外部, HTTPS出网) ────────────────┘                     │
└────────────────────────────────────────────────────────────────┘
```

### 1.2 docker-compose.yml（完整定义，第二阶段随代码交付）

```yaml
services:
  mysql:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: ai_mall
    volumes:
      - mysql-data:/var/lib/mysql
      - ./backend/src/main/resources/db/init:/docker-entrypoint-initdb.d:ro  # 自动执行建表SQL
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 10s
      retries: 10

  redis:
    image: redis:7-alpine
    command: redis-server --requirepass ${REDIS_PASSWORD}
    volumes: [redis-data:/data]

  etcd:            # Milvus standalone 依赖
    image: quay.io/coreos/etcd:v3.5.14
    environment: { ETCD_AUTO_COMPACTION_MODE: revision, ... }
    volumes: [etcd-data:/etcd]

  minio:           # Milvus 对象存储依赖
    image: minio/minio:latest
    command: minio server /minio_data
    environment:
      MINIO_ROOT_USER: ${MINIO_USER}
      MINIO_ROOT_PASSWORD: ${MINIO_PASSWORD}
    volumes: [minio-data:/minio_data]

  milvus:
    image: milvusdb/milvus:v2.5.x
    command: ["milvus", "run", "standalone"]
    depends_on: [etcd, minio]
    volumes: [milvus-data:/var/lib/milvus]
    # 仅内部网络，不映射宿主端口

  ai-service:
    build: ./ai-service
    env_file: ./ai-service/.env
    expose: ["8000"]          # 不 ports: 对外 —— 架构红线
    depends_on:
      mysql: { condition: service_healthy }
      milvus: { condition: service_started }
    deploy:
      replicas: 1             # 水平扩展：改副本数即可（无状态）
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]

  backend:
    build: ./backend
    env_file: ./backend/.env
    ports: ["8080:8080"]      # 唯一对外业务入口
    depends_on:
      mysql: { condition: service_healthy }
      ai-service: { condition: service_started }

  frontend:
    build: ./frontend         # 多阶段构建: node→nginx
    ports: ["80:80"]
    depends_on: [backend]

volumes:
  mysql-data: redis-data: etcd-data: minio-data: milvus-data:
```

**编排要点**：
1. `ai-service` 用 `expose` 不用 `ports` —— Python 服务永不直接暴露给外网（架构红线）。
2. MySQL 建表 SQL 挂载到 `docker-entrypoint-initdb.d`，首次启动自动初始化（库名 ai_mall）。
3. 健康检查 + `depends_on.condition` 保证启动顺序：mysql(healthy) → backend。
4. 全部敏感值来自 `.env` 文件（gitignore），compose 文件可安全入库。
5. Milvus standalone 自带 etcd/minio 依赖，生产可替换集群版，应用配置不变。

## 2. 各服务环境变量配置说明

### 2.1 backend（SpringBoot）`.env`

| 变量 | 示例 | 说明 |
|------|------|------|
| `SPRING_PROFILES_ACTIVE` | docker | dev/test/prod/docker 多环境 |
| `MYSQL_HOST/PORT/DB` | mysql / 3306 / ai_mall | 连接串组成 |
| `MYSQL_USERNAME/PASSWORD` | root / *** | 数据库凭据 |
| `REDIS_HOST/PORT/PASSWORD` | redis / 6379 / *** | 缓存 |
| `JWT_SECRET` | ≥64位随机串 | 签名密钥（HS512） |
| `JWT_ACCESS_TTL_MINUTES` | 120 | 访问令牌有效期 |
| `JWT_REFRESH_TTL_DAYS` | 7 | 刷新令牌有效期 |
| `AI_SERVICE_BASE_URL` | http://ai-service:8000 | 上游 AI 服务 |
| `INTERNAL_TOKEN` | 随机32+位 | 服务间令牌（与 ai-service 一致） |
| `FILE_STORAGE_PATH` | /data/files | 知识库文档上传目录（挂载卷） |
| `IMAGE_STORAGE_PATH` | /data/images | 商品图片目录（挂载卷） |
| `RESILIENCE_TIMEOUT_MS` | 60000 | WebClient 响应超时（LLM 长流） |
| `CHAT_RATE_LIMIT` | 20 | 每用户每分钟对话数 |

### 2.2 ai-service（Python）`.env`

| 变量 | 示例 | 说明 |
|------|------|------|
| `LLM_API_BASE` | https://api.xxx.com/v1 | OpenAI 兼容地址 |
| `LLM_API_KEY` | sk-*** | ⚠️ 绝不入库不入前端 |
| `LLM_CHAT_MODEL` | deepseek-chat / gpt-4o 等 | 对话模型 |
| `LLM_INTENT_MODEL` | 轻量模型 | 意图识别（低延迟低成本） |

| `EMBEDDING_MODEL` | qwen3-embedding:4b | 本地 Qwen3 向量模型 |
| `EMBEDDING_DIM` | 1024 | Qwen3 输出及 Milvus collection 维度 |

| `MILVUS_COLLECTION` | kb_chunks | 集合名 |
| `BACKEND_BASE_URL` | http://backend:8080 | 回调后端（工具） |
| `INTERNAL_TOKEN` | 与后端一致 | 服务间令牌 |
| `TOOL_CALLBACK_TIMEOUT_S` | 3 | 工具回调超时 |
| `MAX_TOOL_LOOPS` | 4 | 工具循环上限 |
| `LINK_GUARD_ENABLED` | true | 内联链接输出后验校验开关 |
| `LOG_LEVEL` | INFO | 日志级别 |

> Embedding 仅通过本地 Ollama 提供；不要把其他模型生成的向量写入当前 Qwen3 collection。

### 2.3 frontend

| 变量 | 说明 |
|------|------|
| `VITE_API_BASE` | dev 用 `/api`(proxy→8080)；prod 构建时注入后端地址 |
| `VITE_SSE_URL` | SSE 端点（一般与 API_BASE 同源） |

## 3. 本地开发环境搭建步骤

### 3.1 前置依赖

| 工具 | 版本 | 用途 |
|------|------|------|
| JDK | 17+ | 后端 |
| Maven | 3.9+ | 后端构建 |
| Node.js | 20 LTS+ | 前端 |
| pnpm | 9+ | 前端包管理 |
| Python | 3.13 | AI 服务 |
| uv / pip | - | Python 依赖（推荐 uv） |
| Docker Desktop | 最新 | 基础设施（mysql/redis/milvus） |

### 3.2 步骤（三服务分离开发，基础设施容器化）

```bash
# ① 基础设施（只起依赖中间件）
docker compose up -d mysql redis etcd minio milvus

# ② 初始化数据库（首次）
docker exec -i <mysql容器> mysql -uroot -p$MYSQL_ROOT_PASSWORD \
  ai_mall < backend/src/main/resources/db/init/V1__init.sql

# ③ AI 服务
cd ai-service
cp .env.example .env            # 填 LLM_API_KEY 等
uv venv && uv pip install -r requirements.txt   # 或 python -m venv
uvicorn app.main:app --reload --port 8000

# ④ 后端
cd backend
cp .env.example .env            # 填 JWT_SECRET 等（dev profile 连 localhost）
mvn spring-boot:run -Dspring-boot.run.profiles=dev

# ⑤ 前端
cd frontend
pnpm install
pnpm dev                        # http://localhost:5173 (proxy /api→8080)

# ⑥ 验证链路
curl http://localhost:8080/actuator/health
curl http://localhost:8000/health
# 浏览器登录 admin/123456 → 商品管理确认种子商品 → 上传知识文档 → 对话测试链接跳转
```

### 3.3 一键启动（演示/验收用）

```bash
cp backend/.env.example backend/.env && cp ai-service/.env.example ai-service/.env
# 编辑两个 .env 填入密钥
docker compose up -d --build
docker compose ps              # 全部 healthy 即成功
```

> 种子账号：admin（管理员）/ agent01（客服）/ customer01（买家），密码均为 123456；种子商品 5 件（手机×3、笔记本、手表）。

## 4. 生产环境部署建议

| 主题 | 建议 |
|------|------|
| 反向代理 | 前置 Nginx/云 LB 终结 HTTPS；SSE 需 `proxy_buffering off; proxy_read_timeout 300s;` 否则流被缓冲 |
| 证书 | 全站 HTTPS（JWT 明文传输必须加密通道） |
| AI 服务扩容 | `docker compose up -d --scale ai-service=3` + LB 轮询（无状态天然支持） |
| 后端扩容 | 多实例 + Redis 共享限流/黑名单；SSE 长连接场景建议单层后端或 ip_hash |
| 数据备份 | MySQL 每日全量+binlog（订单交易数据）；Milvus 可由 kb_chunk 元数据 + 源文件**重建** |
| 密钥管理 | 生产 .env 由运维平台（Vault/云 Secret）注入，CI/CD 不落盘 |
| 日志 | 容器 stdout → 集中采集（EFK/Loki） |
| 升级策略 | 滚动更新；SSE 优雅停机：后端先停接新流，等存量流结束（max 5min）再下线 |
| LLM 成本护栏 | message.token_usage 按日聚合告警（token 突增>200% 报警） |

## 5. 监控与可观测性方案

### 5.1 三层观测

| 层 | 手段 | 内容 |
|----|------|------|
| 基础设施 | Docker healthcheck + (可选) Prometheus | CPU/内存/磁盘/容器状态 |
| 应用 | Spring Actuator(`/actuator/health,metrics`) + AI `/health` | JVM、WebClient 连接池、熔断器状态、Milvus/LLM 连通性 |
| 业务 | message 表（token_usage/latency）+ 统计接口 | token 成本、首响延迟、工具调用次数、热门问题 |

### 5.2 链路追踪（traceId 贯穿）

```
前端 axios 生成 traceId(uuid) → header X-Trace-Id
→ 后端 MDC 注入(日志前缀) + 透传给 AI 服务 header
→ AI 服务日志前缀 + 回调后端工具时携带
→ 错误响应体返回 traceId → 用户报障可直接定位全链路日志
```

### 5.3 告警清单（最小集）

| 告警项 | 阈值 | 级别 |
|--------|------|------|
| 后端 /health DOWN | 1 次 | P0 |
| AI /health 中 llm=DOWN | 1 次 | P0 |
| 熔断器 OPEN | 5 分钟内≥1 次 | P1 |
| SSE error 事件率 | >5%（10分钟窗口） | P1 |
| LLM 日 token 消耗 | >均值 200% | P2 |
| 链接降级次数（link_guard） | >10 次/日（id 编造征兆） | P2 |

## 6. 安全加固清单

| # | 项 | 措施 | 层 |
|---|----|------|-----|
| 1 | 密钥零硬编码 | 全部环境变量；CI 增加 secret-scan（gitleaks） | 全局 |
| 2 | AI 服务不暴露 | compose 仅 expose；生产安全组封禁 8000 | 部署 |
| 3 | 服务间认证 | INTERNAL_TOKEN 双向校验 + 定期轮换 | 后端/AI |
| 4 | JWT 安全 | HS512 + ≥64 位随机 secret；登出黑名单；refresh 一次性 | 后端 |
| 5 | SQL 注入 | MyBatis-Plus 预编译；禁用 ${} 拼接 | 后端 |
| 6 | XSS | 前端 v-html 仅用于 marked 渲染 + DOMPurify 消毒 | 前端 |
| 7 | 越权 | 会话/订单归属校验；工具回调身份注入 | 后端 |
| 8 | 传输加密 | 全站 HTTPS；SSE 同源代理 | 部署 |
| 9 | 文件上传 | 白名单(pdf/md/txt)+20MB+UUID 重命名+存储目录不可执行 | 后端 |
| 10 | 限流防刷 | 登录防爆破(5次/分钟/IP)、对话 QPS | 后端 |
| 11 | Prompt 注入 | 检索内容定界符隔离+身份服务端注入+输出脱敏 | AI |
| 12 | 链接安全 | 前端仅渲染 mall:// 白名单；AI 输出后验校验；toRoute 正则白名单 | AI/前端 |
| 13 | 库存并发 | 下单行锁+事务防超卖 | 后端 |
| 14 | 依赖安全 | 定期 mvn dependency-check / pip-audit / pnpm audit | CI |

## 7. 常见部署问题速查（第三阶段详化）

| 症状 | 原因 | 处理 |
|------|------|------|
| SSE 前端无输出/整段一起出 | Nginx 缓冲 | `proxy_buffering off` |
| 后端报 5001 | ai-service 未起/INTERNAL_TOKEN 不一致 | 对比两侧 .env |
| Milvus 检索空 | collection 未建/维度不匹配 | 检查 EMBEDDING_DIM 与建集合参数 |
| AI 回答商品链接点击 404 | 商品被删除/下架或 id 编造 | 路由守卫兜底 404；查 link_guard 日志 |
| 下单报 2006 | 并发库存不足 | 正常业务行为，前端提示 |
| 首次对话很慢 | Embedding/LLM 冷启动 | 预热脚本（第二阶段提供） |
| MySQL 中文乱码 | 未用 utf8mb4 | 建库脚本已固定，检查连接参数 |
