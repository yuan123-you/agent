# 大规模电商知识库与 RAG 分块设计

**日期：** 2026-08-23  
**状态：** 已确认

## 目标

为 AI Mall 增加一套可复现的合成电商知识库：15 份分层抽样文档、约 1,000 个实际分块，用于在大数据量、相似内容、条件例外和跨文档问题下测试 Agent 工具选择与 RAG 检索质量。

## 数据集

数据覆盖平台政策、支付发票、会员营销、物流履约、售后维权、账户安全、商家治理，以及 16 个商品类目的选购、规格、使用、保养、兼容性和故障排查。包含口语同义词、相似型号、地域/渠道差异、有效期、前置条件、例外条款和硬负样本。

目标分布为 15 份文档：FAQ 6、INTRO 5、POLICY 4；格式为 MD 12、TXT 2、PDF 1，并跨完整 300 场景源目录等距抽样以保留主题覆盖。所有文档标注为合成测试数据。生成器固定随机种子，输出清单记录标题、路径、格式、类型、主题和评测标签。

## 架构

`backend/scripts/generate_kb_dataset.py` 负责确定性地产生资源文件、清单和 RAG 评测集。生成产物存入 `backend/src/main/resources/kbseed/generated/`，随 Spring Boot 包发布。

后端以清单驱动批量播种。启动时只保证数据库记录和对象存储文件存在，不同时触发全部摄取；调度器根据最大并发与批大小领取 PENDING/FAILED/超时 PROCESSING 文档，受控调用 AI 服务。标题作为当前模式下的幂等键，生成标题带稳定编号以避免碰撞。原平台规则种子继续保留并纳入统一恢复逻辑。

批量知识库默认开启，但允许通过环境变量关闭；批量大小、最大并发和超时均可配置。清库重建后会自动恢复，单份失败不会阻塞其余文档。

## 分块

分块参数从硬编码改为配置：默认 `chunk_size=600`、`chunk_overlap=90`，二者按字符计数。Markdown 先按 H1/H2/H3 标题切分，再使用中文友好的段落、换行、句号、问号、感叹号、分号和逗号递归切分。每块保留标题路径上下文。

配置必须满足 `chunk_size >= 200`、`chunk_overlap >= 0` 且 `chunk_overlap < chunk_size`；非法配置在服务启动时快速失败。环境变量为 `RAG_CHUNK_SIZE` 与 `RAG_CHUNK_OVERLAP`。

## Embedding 顺序降级

Embedding 固定使用本地 Ollama `qwen3-embedding:4b`，输出维度为 1024。文档与查询共用同一客户端，禁止向当前 collection 混入其他模型的向量。

## 评测

生成器同时输出 `eval/dataset/kb_large_rag.jsonl`，每条包含 query、expected_doc_key、must_hit、doc_type、difficulty 和 note。覆盖直接事实、口语改写、条件/例外、多跳、版本与地域区分、硬负样本。

测试验证生成器的确定性、数量、分布、清单引用完整性和预计分块量；验证后端清单解析、幂等播种和受控领取；验证 AI 分块边界、重叠、标题上下文与配置校验。最终执行全量 Python/Java 测试并报告数据统计。

## 非目标

不采集或复制真实平台受版权保护的文案；不将合成规则表示为真实法律承诺；不替换 Milvus，也不重构 Agent 协议。
