# 管理员用户能力与数据看板设计

日期：2026-08-23

## 1. 背景与目标

AI Mall 已有管理员用户列表、商品管理和基础 AI 使用统计，但管理员不能直接创建客服账号，用户列表混合展示不同角色，注册入口仅创建买家，且管理员缺少覆盖交易、用户、商品、客服与 AI 的综合运营看板。

本次改动目标：

1. 管理员只能新增客服账号。
2. 买家与卖家通过注册页的独立入口自行注册。
3. 用户管理按买家、卖家、客服三个 Tab 隔离展示，排除管理员并取消角色转换。
4. 管理员商品管理取消编辑能力，但保留新建及上下架；卖家自有商品编辑不受影响。
5. 管理员登录后默认进入综合数据看板。
6. 内部角色代码继续使用 `MERCHANT`，所有面向用户的角色文案统一为“卖家”。
7. 为项目初始化 Git，并在验证完成后提交代码；敏感信息、日志与构建产物不得入库。

## 2. 选定方案

采用薄服务层方案，沿用 Vue 3、Spring Boot、MyBatis-Plus 与现有数据模型：

- `RegistrationService` 负责买家/卖家注册及卖家建店事务。
- `AdminUserService` 负责客服创建、分角色查询及账号启停。
- `AdminDashboardService` 负责运营看板聚合。
- Controller 只负责参数校验、权限入口和响应包装。
- Mapper 提供必要的数据库聚合查询，不引入统计快照表或定时任务。

不进行完整 RBAC 重构，也不把业务逻辑继续堆入现有 Controller。

## 3. 前端信息架构

### 3.1 管理员导航

管理员登录后默认路由为 `/admin/dashboard`。后台侧栏顺序为：

1. 数据看板
2. 商品管理
3. 订单管理
4. 知识库
5. 用户管理
6. 使用统计

“使用统计”保留为 AI 详细统计页；“数据看板”承担跨业务域的综合概览。

### 3.2 用户管理

用户管理页包含三个 Tab：

- 买家（`CUSTOMER`）
- 卖家（`MERCHANT`）
- 客服（`AGENT`）

切换 Tab 后清空当前列表并按角色重新加载。管理员账号始终不展示。搜索、滚动加载、启用和禁用能力保留；角色转换按钮及逻辑全部移除。只有客服 Tab 展示“新增客服”按钮。

新增客服弹窗字段：用户名、初始密码、昵称、可选手机号。前端不提交可选择的角色，后端固定创建 `AGENT`。

### 3.3 注册页

登录入口保持不变；注册区域拆分为“买家注册”和“卖家注册”：

- 买家：用户名、密码、昵称、可选手机号。
- 卖家：用户名、密码、昵称、可选手机号、必填店铺名称。

卖家注册成功后可使用同一账号登录卖家工作台。店铺 Logo、简介和地址初始为空，后续由卖家补充。所有界面可见的 `MERCHANT` 或“商家”角色名称统一显示为“卖家”；代码、数据库、JWT 与接口中的角色值保持 `MERCHANT`。

### 3.4 管理员商品管理

管理员商品页保留新建商品、搜索、状态筛选和上下架。移除编辑按钮、编辑态分支以及管理员商品更新 API 的前端调用。新建弹窗只承担创建功能。卖家工作台中对自有商品的编辑能力不变。

## 4. 后端接口与数据流

### 4.1 注册接口

- `POST /api/v1/auth/register/customer`
  - 创建角色固定为 `CUSTOMER` 的用户。
- `POST /api/v1/auth/register/merchant`
  - 接收通用注册字段和 `shopName`。
  - 在同一数据库事务内检查用户名、创建 `MERCHANT` 用户、创建 `merchant` 资料。
- `POST /api/v1/auth/register`
  - 为旧客户端保留，语义继续等同买家注册。

卖家资料初始状态为 `ACTIVE`，与用户账号同步启用。任一步骤失败时事务整体回滚，不允许产生无店铺卖家或无账号店铺。

### 4.2 管理员用户接口

- `POST /api/v1/admin/users/agents`
  - 仅创建角色固定为 `AGENT` 的客服。
  - 请求字段为用户名、密码、昵称及可选手机号。
- `GET /api/v1/admin/users?role=CUSTOMER|MERCHANT|AGENT`
  - 分页、关键词搜索沿用现有行为。
  - 角色参数仅接受三种非管理员角色。
  - 即使未传角色也必须排除 `ADMIN`。
- `PUT /api/v1/admin/users/{id}/status`
  - 仅接受 `ACTIVE` 或 `DISABLED`。
  - 拒绝操作管理员和当前登录管理员本人。

旧通用更新接口不再允许修改角色，防止旧客户端或篡改请求绕过页面限制。

### 4.3 数据看板接口

新增 `GET /api/v1/admin/dashboard`，响应结构：

```json
{
  "summary": {
    "userCount": 0,
    "merchantCount": 0,
    "onSaleProductCount": 0,
    "todayOrderCount": 0,
    "todayGmv": 0,
    "todayConversationCount": 0
  },
  "orderTrend": [
    { "date": "2026-08-17", "orderCount": 0, "gmv": 0 }
  ],
  "orderStatusDistribution": [
    { "status": "PAID", "count": 0 }
  ],
  "operations": { "waitingHumanConversationCount": 0 },
  "aiQuality": {
    "replySuccessRate": 0,
    "toolCallRatio": 0,
    "avgLatencyMs": 0,
    "totalTokens": 0
  },
  "topQuestions": [],
  "toolCalls": []
}
```

指标定义：

- 用户总数：非逻辑删除的非管理员用户总数。
- 卖家总数：角色为 `MERCHANT` 的有效用户数量。
- 在售商品数：状态为 `ON_SALE` 的商品数量。
- 今日订单数：服务器 `Asia/Shanghai` 当日创建的订单数。
- 今日成交额：今日订单中已进入有效支付/履约状态订单的实付金额合计，取消或关闭订单不计入。
- 今日 AI 会话数：沿用现有会话统计口径。
- 近 7 日趋势：含今天在内的 7 个自然日，缺失日期由服务层补零。
- 订单状态分布：当前各业务订单状态数量。
- 待人工会话：当前处于等待人工接入状态的会话数。
- AI 质量、热门问题、工具排行：复用现有统计查询与纯聚合逻辑，避免重复口径。

金额在 Java 与数据库聚合中使用 `BigDecimal`，不得经由浮点数计算。接口没有数据时返回零值或空数组，不返回 `null`。第一版固定展示今日和近 7 日，不提供自定义日期筛选。

## 5. 校验、安全与错误处理

- 用户名：4～32 位字母、数字或下划线。
- 密码：6～32 位。
- 昵称：必填，最长 32 字。
- 手机号：可选；填写时必须符合现有手机号规则。
- 店铺名：卖家注册必填，最长 64 字。
- 用户名重复返回现有“用户名已存在”业务错误。
- 客服创建接口后端固定角色，不能通过请求体创建管理员、买家或卖家。
- 用户启停接口拒绝非法状态、管理员目标和当前操作者本人。
- 前端表单提交期间禁用按钮，成功后关闭弹窗并刷新当前 Tab；失败信息沿用全局请求拦截器。
- 看板查询异常由现有全局异常处理器统一包装；不得用部分伪造数据掩盖数据库错误。

## 6. 测试策略

所有生产改动按 TDD 实施，先运行新增测试并确认因功能缺失而失败，再写最少实现使其通过。

### 6.1 后端测试

- 买家注册写入 `CUSTOMER`。
- 卖家注册写入 `MERCHANT` 并创建关联店铺。
- 重复用户名被拒绝。
- 卖家建店失败时事务回滚。
- 管理员接口只能创建客服。
- 用户列表始终排除管理员并正确按角色过滤。
- 更新接口不能再转换角色，但可启停买家、卖家和客服。
- 看板今日汇总、有效 GMV、状态分布计算正确。
- 近 7 日趋势缺失日期补零。
- 空数据返回完整零值结构。
- AI 指标复用后的统计口径与现有测试保持一致。

### 6.2 前端测试

- 买家和卖家注册调用各自接口并提交正确字段。
- 卖家注册必须填写店铺名。
- 用户 Tab 与角色代码映射正确，列表不出现角色转换操作。
- 仅客服 Tab 展示新增客服入口。
- 看板数据转换、状态中文映射和空值展示正确。
- 管理员商品页不再引用更新接口或进入编辑态。
- 所有可见卖家角色文案均为“卖家”。

### 6.3 完成验证

- `mvn test` 通过且无新增警告。
- `npm test` 通过。
- `npm run build` 通过。
- 检查 Git 变更中无 `.env`、日志、依赖、构建产物或密钥。

## 8. 明确不在本次范围内

- 创建或编辑管理员账号。
- 管理员对用户执行角色转换。
- 管理员编辑已有商品。
- 移除卖家对自有商品的编辑能力。
- 将内部 `MERCHANT` 角色代码或数据库值改成中文。
- 店铺审核流、资质上传和管理员审批。
- 自定义看板日期范围、统计快照表和定时汇总任务。
- Git 远程仓库配置与推送。
