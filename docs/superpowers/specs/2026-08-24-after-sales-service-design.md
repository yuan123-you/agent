# AI Mall 售后服务与客服工作台增强设计

- 日期：2026-08-24
- 状态：已在对话中确认
- 范围：独立售后工单、买家/卖家/客服协同、客服聊天联动、模拟退款

## 1. 背景与目标

AI Mall 已有订单、AI 对话、转人工、客服工作台和退换货知识库，但没有结构化的售后申请与处理流程。本次新增独立售后子系统，并增强客服工作台，使买家可从订单发起售后，卖家与客服可按职责协同处理，聊天可创建或关联售后单。

本次继续使用现有 `CUSTOMER`、`MERCHANT`、`AGENT`、`ADMIN` 四种角色，不增加角色；退款仅模拟业务结果，不连接真实支付渠道。

## 2. 方案选择

采用“独立售后工单，聊天通过关联表联动”的方案。

未采用的方案：

- 将售后信息仅记录在聊天中：无法可靠筛选、统计和追踪状态，也不利于卖家协同。
- 建立通用可配置工单与流程引擎：超出当前需求，增加不必要的开发和维护成本。

售后逻辑集中在后端 `aftersale` 模块。订单、聊天、卖家和客服控制器只通过该模块的接口使用售后能力，不直接修改售后状态。

## 3. 角色职责

### 3.1 买家

- 从本人订单商品发起售后；
- 查看、搜索和筛选本人售后单；
- 补充说明和图片凭证；
- 填写退货物流；
- 申请平台介入；
- 确认换货收货；
- 在允许的状态撤销售后；
- 创建或打开与售后单关联的客服会话。

### 3.2 卖家

- 查看仅包含本店商品的售后单；
- 同意、拒绝或要求买家补充材料；
- 确认收到退货；
- 填写换货物流；
- 公开回复买家；
- 请求平台客服协助。

卖家不能执行模拟退款、修改退款金额上限、查看内部备注、访问其他店铺工单或在平台介入后改变最终结果。

### 3.3 客服与管理员

- 查看和介入全部售后单；
- 处理平台问题及买卖争议；
- 修改优先级；
- 添加内部备注；
- 调整最终退款金额；
- 执行模拟退款；
- 转交给其他启用状态的客服；
- 完成或关闭工单。

`ADMIN` 沿用现有权限，可执行客服侧售后操作；不新增管理员专属售后角色。

## 4. 售后类型与问题分类

### 4.1 售后方式

- `RETURN_REFUND`：退货退款；
- `EXCHANGE`：换货；
- `REFUND_ONLY`：仅退款；
- `ISSUE_REPORT`：问题反馈。

每个申请必须关联一个订单项。申请数量不得超过订单项剩余可售后数量；期望退款金额不得超过按申请数量计算的剩余可退款金额。

### 4.2 一级问题分类

- `PERSONAL`：个人原因，如不喜欢、买错、尺寸不合适、地址或个人操作问题；
- `QUALITY`：商品质量，如损坏、功能异常、与描述不符、临期；
- `MERCHANT`：卖家问题，如错发、漏发、虚假发货、拒绝履约、服务态度；
- `PLATFORM`：平台问题，如支付、账户、系统故障、平台规则或争议处理。

前端为一级分类提供固定的常见具体原因，同时允许买家填写补充说明。本次不实现可配置分类系统。

## 5. 分流与状态模型

### 5.1 初始分流

- `PLATFORM` 问题直接分配给平台客服；
- 其他问题默认分配给订单商品所属卖家；
- 买家可在卖家拒绝后或处理超时后申请平台介入；
- 客服可主动介入任意工单；
- 平台介入后卖家不能改变最终处理结果。

### 5.2 状态

| 状态 | 含义 |
| --- | --- |
| `PENDING_MERCHANT` | 等待卖家处理 |
| `PENDING_PLATFORM` | 等待客服处理或平台介入 |
| `PENDING_CUSTOMER` | 等待买家补充材料、退货或确认 |
| `RETURNING` | 买家已填写退货物流，等待卖家确认收货 |
| `PENDING_REFUND` | 退款条件已满足，等待客服执行模拟退款 |
| `EXCHANGING` | 卖家执行换货并填写新物流 |
| `COMPLETED` | 已退款、已换货或问题已解决 |
| `REJECTED` | 申请被拒绝，买家仍可申请平台介入 |
| `CANCELLED` | 买家主动撤销 |

当前处理方单独记录为 `CUSTOMER`、`MERCHANT` 或 `PLATFORM`，用于队列归属和界面提示；它不是新的用户角色。

### 5.3 状态动作

模块支持以下业务动作：

- `APPROVE`
- `REJECT`
- `REQUEST_INFO`
- `SUPPLY_INFO`
- `SUBMIT_RETURN`
- `CONFIRM_RETURN`
- `SUBMIT_EXCHANGE_SHIPMENT`
- `CONFIRM_EXCHANGE`
- `REQUEST_PLATFORM`
- `TAKE_OVER`
- `SIMULATE_REFUND`
- `CANCEL`
- `COMPLETE`
- `TRANSFER`

模块根据“当前状态、当前处理方、操作人身份、资源归属、动作”统一判断动作是否合法。前端隐藏不可用按钮只用于改善体验，不代替后端鉴权和状态校验。

### 5.4 主要流程

退货退款：

```text
提交申请 → 卖家/客服审核 → 买家填写退货物流 → 卖家确认收货
→ 客服执行模拟退款 → 完成
```

换货：

```text
提交申请 → 卖家审核 → 买家填写退货物流 → 卖家确认并填写换货物流
→ 买家确认收货 → 完成
```

仅退款：

```text
提交申请 → 卖家审核 → 客服执行模拟退款 → 完成
```

平台问题可跳过卖家审核，由客服直接解决或进入模拟退款。卖家拒绝必须填写原因；买家可补充凭证并申请平台介入。客服介入后可维持拒绝、要求补充材料、批准退换货或调整最终退款金额。

买家只能在工单尚未进入 `PENDING_REFUND`、`EXCHANGING` 或 `COMPLETED` 时撤销。所有状态变化均追加记录，不覆盖历史。

## 6. 数据设计

新增 Flyway 迁移 `V6__after_sale_workflow.sql`，建立以下表及必要索引和唯一约束。

### 6.1 `after_sale`

主要字段：

- 售后编号；
- 订单 ID、订单项 ID；
- 买家 ID、卖家 ID；
- 售后方式、问题分类、具体原因、描述；
- 申请数量；
- 期望退款金额、最终退款金额；
- 优先级；
- 状态、当前处理方、当前客服 ID；
- 状态进入时间；
- 退货物流公司和单号；
- 换货物流公司和单号；
- 创建、更新和完成时间。

订单主状态不用于表达单个商品的售后进度。订单详情通过售后聚合信息展示“售后中、已退款、已换货”和累计退款金额。

### 6.2 `after_sale_record`

记录：

- 售后单 ID；
- 动作类型；
- 操作人 ID 和操作时角色；
- 操作前后状态；
- 公开回复或操作说明；
- 是否仅内部可见；
- 创建时间。

状态变更、回复、内部备注、转交、平台介入和模拟退款都追加为记录。

### 6.3 `after_sale_attachment`

记录售后单、处理记录（可选）、对象存储键、原始文件名、内容类型、文件大小、上传人和创建时间。

凭证限制：JPG、PNG、WEBP；单文件不超过 5 MB；每个售后单最多 6 张。对象名由系统生成，读取前验证售后访问权限。

### 6.4 `conversation_after_sale`

字段：

- 会话 ID；
- 售后单 ID；
- 创建人 ID；
- 创建时间。

会话与售后为多对多关系：一个会话可讨论多个售后单，同一售后单也可在后续会话中继续咨询。关联时必须验证会话和售后单属于同一买家。

## 7. 后端接口与事务

控制器路径：

```text
/api/v1/after-sales/**
/api/v1/merchant/after-sales/**
/api/v1/workbench/after-sales/**
```

分别作为买家、卖家和客服适配层，调用统一的售后模块。

创建售后单在单个事务中完成：

1. 验证订单属于当前买家；
2. 验证订单状态允许售后；
3. 验证订单项、申请数量和售后期限；
4. 汇总已有进行中及已退款数量；
5. 校验期望退款金额上限；
6. 创建售后主记录；
7. 创建首条处理记录；
8. 按需关联会话。

状态操作使用包含当前状态条件的原子更新。发生并发修改时返回“工单状态已变化，请刷新后重试”，防止重复介入、确认或退款。

模拟退款要求：

- 操作人是客服或管理员；
- 工单处于 `PENDING_REFUND`；
- 最终退款金额大于零且不超过剩余可退款金额；
- 工单尚无成功模拟退款记录。

成功后追加不可重复的退款记录并完成工单，不调用外部支付渠道。

## 8. 页面与交互

### 8.1 买家端

订单列表和详情中的订单商品显示“申请售后”或“查看售后”。未支付、已取消、剩余可售后数量为零、已有覆盖全部数量的进行中售后或超过售后期限时不能申请。

新增：

- 售后申请页：商品摘要、售后方式、问题分类、具体原因、数量、金额、描述、图片凭证、是否同时创建客服会话；
- 我的售后列表：状态和方式筛选，按售后号、订单号、商品名搜索；
- 售后详情：状态、当前处理方、超时提示、公开时间线、补充凭证、退货物流、申请介入、撤销、确认换货等；
- 联系客服：打开已关联会话，未关联时创建并关联。

### 8.2 卖家端

新增“售后管理”：

- 待处理、等待买家、退货中、换货中、已完成标签；
- 按售后号、订单号、商品、买家昵称搜索；
- 按类型、问题分类、状态和优先级筛选；
- 查看凭证、订单商品和公开时间线；
- 同意、拒绝、要求补充材料、确认退货、填写换货物流、公开回复和请求平台协助。

### 8.3 客服工作台首页

在“待接入”和“服务中”之外增加售后队列：

- 搜索会话号、售后号、订单号和买家昵称；
- 按状态、问题分类、优先级、当前处理方和是否超时筛选；
- 默认按“超时、高优先级、等待时间”排序；
- 增加待处理售后和超时售后统计；
- 卡片展示问题类型、状态、商品、买家、卖家、等待时长和优先级。

超时由“状态进入时间 + 对应阈值”动态计算，不新增定时任务。

### 8.4 客服会话详情

页面调整为左侧聊天主区域和右侧信息栏。

左侧提供消息、AI 回复、人工回复和快捷回复。右侧展示买家信息、最近订单、关联售后单、售后时间线和内部备注。

客服可从会话创建售后、关联已有售后、修改优先级、添加内部备注、介入、更新状态、调整退款金额、执行模拟退款、转交和结束处理。

固定快捷回复由前端常量维护，不新增模板管理表。默认包含核实订单、补充凭证、转交卖家、平台介入、模拟退款完成和填写退货物流等模板。

### 8.5 转交

- 仅客服或管理员可将会话或平台售后转交给其他启用客服；
- 转交必须填写原因；
- 转交后原客服只读，目标客服进入服务中或待处理队列；
- 转交写入售后记录或会话系统消息；
- 不改变卖家工单的店铺归属。

## 9. 权限与错误处理

后端使用登录身份确定资源归属，不接受前端提交的买家、卖家或操作人 ID。

业务错误包括：

- 订单不支持售后；
- 可售后数量不足；
- 退款金额超过上限；
- 存在冲突的售后申请；
- 当前状态不允许操作；
- 无权查看或处理；
- 工单已被其他人更新；
- 凭证格式、大小或数量不合法；
- 关联会话与售后单买家不一致；
- 目标客服不存在或已禁用。

前端保留用户已填写内容并显示中文错误。列表轮询失败时不清空现有数据；发生状态冲突时刷新最新详情。

## 11. 非目标

本次不实现：

- 真实支付宝或微信退款；
- 新角色或动态权限系统；
- 通用可配置流程引擎；
- 管理员维护快捷回复模板；
- 视频凭证；
- 物流公司接口；
- 自动定时裁决；
- 多级审批。
