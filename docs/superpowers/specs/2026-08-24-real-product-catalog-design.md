# 真实商品目录替换与扩充设计

**日期：** 2026-08-24  
**状态：** 已确认，待实施计划  
**目标：** 将现有 512 件虚构商品原位替换为真实商品，再增加 2000 件真实商品，使有效商品总数严格为 2512。

## 1. 范围与约束

- 商品来自公开商品目录、品牌官网、公开 API、公开 Sitemap 或包含 `Product` JSON-LD 的公开页面。
- 不绕过登录、验证码、访问控制或反爬机制；遵守来源站点公开访问规则并实施限速。
- 商品本身不受上市年份限制，但来源页面更新时间或本次成功采集时间必须不早于 2025-01-01。
- 优先使用来源页面声明的更新时间；无法获得时，以本次成功采集时间和响应元数据作为依据。
- 价格是采集时公开参考价，不表示实时最低价；库存和销量是平台演示字段，必须在数据清单和报告中标明为模拟值。
- 无法从来源确认的产地、材质、生产日期等字段保持 `NULL`，不得推测或编造。
- 分类参考国内主流综合电商，可调整为约 20–22 个一级分类；分类数量不强制平均，以真实、可验证数据为优先。

## 2. 数据来源策略

采用“公开目录发现 + 官方或可信公开页面核验”的混合策略：

1. 从公开目录、公开 API、品牌 Sitemap 和结构化商品页面发现候选商品。
2. 优先从品牌官网、官方产品页或可信公开目录获取名称、品牌、型号、图片、价格和规格。
3. 对同一商品以来源商品 ID、规范化品牌/型号和来源 URL 去重；允许真实 SKU/容量/颜色变体，但每个变体必须具有可区分的来源标识或规格。
4. 每条最终数据保留来源名称、来源 URL、来源商品 ID、来源更新时间、采集时间和原始图片 URL。
5. 任何来源无法继续公开访问时，不尝试规避限制，改用其他来源或淘汰候选条目。

不采用纯电商页面爬虫作为唯一来源，因为登录、动态接口、防盗链和页面变化会降低可重复性；也不采用仅依赖旧开放数据集的方案，因为其时效与来源证明通常不足。

## 3. 分类模型

保留现有分类语义并参考国内主流平台重新整理，候选一级分类包括：

- 手机通讯、数码影音、电脑办公、家用电器
- 家居家装、家具、服饰内衣、鞋靴、箱包
- 美妆护肤、个护清洁、食品饮料、生鲜
- 母婴用品、玩具乐器、运动户外、图书文娱
- 汽车用品、宠物生活、医药保健、珠宝钟表

采集器使用稳定的内部分类代码，前端显示中文名称。来源站点的细分类保存在 `specs` 或来源元数据中，不直接扩散为不可控的一级分类。最终报告输出各分类数量；允许某些分类数量较少，由可验证数据较多的分类补足，但总数必须严格为 2512。

## 4. 标准商品记录

最终生成可审计、可重复导入的 JSONL 清单。每条记录至少包含：

- `name`：真实商品名称
- `brand`：真实品牌
- `category`：内部一级分类代码
- `price`、`currency`：采集时公开参考价格及币种
- `stock`、`sales`：平台演示值，并带模拟数据标识
- `description`、`selling_points`
- `specs`：合法 JSON，保存来源可确认的结构化规格
- `origin`、`material`、`production_date`：仅在来源明确提供时写入
- `source_name`、`source_url`、`source_product_id`
- `source_updated_at`、`collected_at`
- `original_image_url`、本地 `image_url`、`image_sha256`
- 内容哈希和采集版本，用于去重、审计和幂等更新

数据库通过新的 Flyway 迁移为 `product` 增加来源、币种、采集时间和图片哈希字段，并建立来源商品唯一索引或等效幂等约束。字段长度需要覆盖真实来源 URL，不沿用当前 255 字符的保守上限。

## 5. 图片处理与存储

所有正式商品必须具有成功下载且可解码的商品图片，不能继续使用 Picsum 或外链热链作为正式主图。

图片流水线：

1. 下载原图，校验 HTTP 状态、最大响应体、实际 MIME 和解码结果。
2. 修正 EXIF 方向，移除不影响展示的元数据。
3. 等比例缩放，最长边默认不超过 1200px；原图更小时不放大。
4. 普通商品图转换为 WebP，默认质量 82；含透明通道的图片使用 WebP lossless。
5. 比较转换前后体积；如果 WebP 未减小，则保留更小且浏览器支持的合法原格式。
6. 以解码后内容或标准化文件的 SHA-256 去重，相同图片只存储一份。
7. 上传至 MinIO 的 `product-images/catalog/` 命名空间。
8. 数据库保存 `/api/v1/product-images/...` 本地访问地址，同时保留原始图片 URL 用于审计。

首版不强制引入 AVIF 编码器。WebP 与当前浏览器和后端接口兼容性更好；只有实测 AVIF 能显著降低总体积且运行环境具备稳定编码支持时，才作为可选编码器加入。图片二进制不提交 Git，标准化清单、采集报告和可重跑脚本提交仓库。

## 6. 组件与数据流

商品目录工具作为独立批处理流水线，包含以下边界清晰的组件：

1. **采集器**：读取公开 API、目录、Sitemap 或公开页面，产生原始候选记录。
2. **标准化器**：统一品牌、名称、分类、价格、币种、规格和文本格式。
3. **质量校验器**：验证来源时间、必填字段、价格、重复项和图片候选。
4. **图片处理器**：下载、解码、缩放、压缩、哈希去重并上传 MinIO。
5. **清单生成器**：输出固定为 2512 条的标准 JSONL 和统计报告。
6. **导入器**：先导入临时区，完成全量校验后事务性写入正式商品表。

数据流为：候选发现 → 来源与时间校验 → 字段标准化 → 去重 → 图片处理与上传 → 生成清单 → 临时导入 → 全量验收 → 正式切换。

采集和图片阶段支持磁盘缓存、断点续传、来源级限速以及有限次数的指数退避。缓存目录与图片工作目录不提交 Git。

## 7. 替换与幂等策略

- 按确定性顺序选择 2512 条合格记录。
- 前 512 条原位更新当前 512 个商品 ID，避免破坏订单、收藏、历史记录等引用。
- 其余 2000 条作为新商品插入。
- 历史订单中的商品名称、图片和价格快照保持不变，因为它们代表下单时状态。
- 与原虚构商品明显不匹配的演示评论在切换过程中清理，避免评论与替换后的商品错配。
- 已存在的真实用户收藏、浏览历史等引用继续指向原商品 ID 对应的新商品；不进行破坏性清库。
- 通过来源商品唯一键和内容哈希实现幂等；任务中断后重跑不会额外生成商品。
- 再次运行同一清单时更新对应商品，而不是插入重复记录。

为避免部分成功状态，图片必须先全部处理并成功上传，随后才执行数据库正式切换。数据库操作在临时表完成校验，并在事务中分批更新/插入；正式切换失败时回滚。

## 8. 错误处理

- 网络错误、429 和可恢复的 5xx 使用有限次数重试与指数退避；永久 4xx 直接淘汰记录。
- 限制单张图片下载大小、请求超时、重定向次数和支持的 MIME，防止异常响应耗尽资源。
- 缺少名称、品牌、有效价格、来源 URL、来源时间依据或可用主图的记录不得进入最终清单。
- `specs` 解析失败、价格非法、图片无法解码或来源重复时记录明确失败原因。
- 单个来源失效不终止候选采集，但最终合格数量不足 2512 时整个发布任务失败。
- 不以虚构商品、占位图、伪造规格或复制记录填补数量缺口。
- 每次运行生成机器可读和人类可读报告，包含候选数、合格数、淘汰原因、来源分布、分类分布、图片失败数、去重数、压缩前后体积及节省比例。

## 9. 测试策略

### 单元测试

- 分类映射、品牌/名称规范化、价格与币种解析。
- 来源更新时间与采集时间规则。
- `specs` JSON 生成、文本清洗和重复商品判定。
- 图片 MIME 检测、EXIF 方向、尺寸限制、透明通道、WebP 转换和 SHA-256 去重。

### 集成测试

- 使用小型固定样本完成采集结果标准化、图片处理、MinIO 上传和数据库导入。
- 验证前 512 条原位更新、后 2000 条新增、事务回滚和中断重跑。
- 同一清单连续导入两次后商品总数和来源唯一键不变化。
- 验证商品图片接口返回的 MIME、内容和缓存行为。

### 回归测试

- 后端商品列表、分类筛选、搜索、详情和管理接口。
- 前端商品列表、详情、收藏和历史记录。
- AI 商品索引与检索对 2512 条目录的处理。

## 10. 最终验收标准

发布前必须同时满足：

1. 有效商品总数严格为 2512。
2. 原 512 条虚构名称和全部 Picsum 图片均不再出现在正式商品中。
3. 每件商品都有真实名称、品牌、分类、正数价格、币种、来源记录和可访问主图。
4. 每条数据的来源更新时间或成功采集时间不早于 2025-01-01。
5. 所有 `specs` 均为合法 JSON，所有正式图片均可解码。
6. 图片通过项目接口访问，响应 MIME 与实际文件格式一致；不存在远程防盗链依赖。
7. 来源唯一键无重复，重复导入不会改变商品总数。
8. 商品列表、详情、分类、搜索和 AI 检索通过回归测试。
9. 采集报告给出来源与分类分布、失败原因、图片压缩前后总体积、压缩率和节省空间。
10. 若任何硬性条件失败，不执行正式数据切换。

## 11. 非目标

- 不保证公开参考价与任一电商平台实时售价一致。
- 不模拟或声称拥有来源站点的实时库存、销量、评价和促销数据。
- 不为完成数量而绕过访问限制或抓取需要授权的内容。
- 不在首版建设长期在线同步服务；本次交付为可审计、可重复运行的批量采集与导入流程。
