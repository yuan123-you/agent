# 工作区全量发布与端到端验收计划

日期：2026-10-27，执行目标：推送当前 dev 工作区全部可提交改动、配套部署 AI/后端/前端、验证真实环境。

1. 发布前：核对 origin/dev 与远端服务器版本；确认干净服务端工作区、容量、健康状态；审查所有 Git 改动和新增文件，密钥、私有交接文件及忽略构建产物不提交。
2. 本地门禁：AI/backend/frontend 全量测试、TypeScript 类型检查、前端生产构建、密钥卫生与离线 eval；将实际结果保留到本地私有发布目录。
3. 提交推送：将可提交工作区完整内容提交到现有 dev 并 push，不强推、不改写历史；核对远端 ref。
4. 部署：服务器只接受 fast-forward；私有发布目录保留旧提交、三个应用镜像、数据库备份与发布日志；先构建，后按 AI→backend→frontend 切换，任何失败恢复旧镜像，保留数据卷，不碰其他项目。
5. 端到端：域名 HTTPS/静态资源/基路径；真实 API 身份与权限；隔离账号的购物车、地址、订单、模拟支付、取消、优惠券、评价、客服工作台；管理员和商家查询/加载/错误界面；真实 KB/商品检索、引用、多轮指代及降级；桌面/移动端浏览器和横向溢出。
6. 隔离与清理：不使用真实交易/个人信息；对自动生成 QA 账号/商品/优惠券禁用或下架，记录清理结果，不删除正常用户数据，不公开凭据/访问令牌/内部地址。
7. 收尾：提交脱敏测试报告，推送并同步服务器文档提交；确认应用源码未变化、服务继续健康，报告已部署代码提交和报告提交的区别。

适用边界：演示环境仅模拟支付/发货；不代表真实支付渠道、邮件/短信、物流或高并发压测已验证。真实模型 CPU 延迟按实测记录，不把 offline/mock 评估当真实端到端结果。
