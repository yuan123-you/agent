### 1.2 路由守卫设计

```
beforeEach:
  1. to.path ∈ 白名单(login/403/404) → next()
  2. 无 accessToken → next('/login?redirect=' + to.fullPath)
  3. accessToken 过期(本地解析exp) → 尝试静默 refresh → 失败清态跳 login
  4. 角色不匹配 → next('/403')
  5. /products/:id 与 /orders/:id 加载失败(不存在) → next('/404')
     （兜底 AI 链接 id 异常的场景）
```

守卫只做**快速本地校验**（JWT payload 的 exp/role），真正合法性由后端校验。

## 5. SSE 流式渲染与高亮链接方案（⭐核心）

### 5.1 为什么不用 EventSource

EventSource 仅支持 GET、无法携带 Authorization 头；对话接口是 POST + JWT，必须用 `fetch` + `ReadableStream` 手动解析 SSE。

### 5.2 useSseChat 封装（接口契约）

```typescript
interface SseHandlers {
  onToken(content: string): void        // 追加到流式消息(含链接语法片段)
  onToolCall(evt: ToolCallEvent): void   // 插入工具卡片(进行中)
  onToolResult(evt: ToolResultEvent): void // 更新卡片(按callId)
  onError(evt: ErrorEvent): void        // 终态: 标记失败+提示
  onDone(evt: DoneEvent): void          // 终态: 落定消息(messageId等)
}

async function streamChat(body: { conversationId: number; content: string },
                          handlers: SseHandlers): Promise<void>
// fetch(POST) + AbortController(暴露stop) + ReadableStream 按行解析
// "event:"/"data:"配对, 空行触发分发, ": ping"忽略
```

### 5.3 ⭐ 高亮链接渲染三件套

#### ① StreamBuffer（流式链接标记缓冲器）

**问题**：token 流会把 `[星耀 X5 Pro](mall://product/1001)` 切成多个片段，直接渲染会闪现半截 markdown 原文。

**方案**：token 追加到缓冲区后，先扫描未闭合的链接标记并扣留：

```typescript
// 伪代码（实现要点）
function extractRenderable(buf: string): { render: string, hold: string } {
  // 从尾向前找最后一个未闭合的 "["：
  //   若其后出现 "](" 且无 ")" 闭合 → "[" 起全部扣留(hold)
  //   若仅有孤立的 "[" 且其后长度 < 最大链接长度(200) → 保守扣留
  // 其余部分(render)交给 marked 渲染
  // done/error 终态时 flush：全部按普通文本处理(容忍未闭合)
}
```

- 流式中：`render` 部分渲染，`hold` 部分等下一批 token；
- 终态：全部 flush，保证不丢字。

#### ② LinkRenderer（marked 自定义 renderer）

```typescript
// marked 配置（实现要点）
const renderer = {
  link({ href, text }) {
    if (href.startsWith('mall://')) {
      // 白名单 scheme → 渲染为高亮 span（不用 <a>，避免浏览器导航）
      // data-route 由 scheme 映射: mall://product/1001 → /products/1001
      //                          mall://order/5001    → /orders/5001
      //                          mall://products?category=PHONE → /products?category=PHONE
      return `<span class="ai-link" data-route="${toRoute(href)}" data-kind="product">${text}</span>`
    }
    // 非 mall://（http/https/javascript:等）→ 纯文本，不可点击（安全红线）
    return `<span class="ai-link-plain">${text}</span>`
  }
}
// 渲染管线: markdown → marked(自定义renderer) → DOMPurify(允许 span 的 class/data-route)
```

#### ③ linkClick（事件委托跳转）

```typescript
// AiMessage.vue 挂载时（实现要点）
container.addEventListener('click', (e) => {
  const target = (e.target as HTMLElement).closest('.ai-link')
  if (target?.dataset.route) router.push(target.dataset.route)
})
// 单点委托，无需为每个链接绑事件；历史消息与流式消息共用同一管线
```

**安全要点**：
1. `data-route` 只能由 `mall://` 白名单映射产生，其他 scheme 一律纯文本；
2. DOMPurify 消毒后再插入，防 XSS；
3. `toRoute()` 做正则白名单校验（`^/(products|orders)(/\d+|\?.*)?$`），非法路由降级为纯文本。

### 5.4 渲染性能约定

1. **流式消息单组件**：streaming 期间 token 只追加到一个响应式字符串；marked 编译节流 50ms（缓冲器天然降低了编译频率）。
2. **长会话**：MessageList 虚拟滚动（或简化为"最近 200 条 DOM + 上滑加载"）。
3. **断线安全**：组件卸载自动 abort；store.streaming 复位。
4. **乐观更新**：买家消息先上屏（pending 灰色），done 后回填 messageId；失败标红重试。

## 6. 关键交互流程图

### 6.1 发送消息 → 高亮链接 → 点击跳转（主链路）

```
用户点击发送/Ctrl+Enter
  → chatStore.sendMessage(content)
     ├─ 乐观插入买家消息(pending)
     ├─ streaming=true, 当前AI消息content=''
     └─ useSseChat.streamChat(...)
          ├─ onToken     → StreamBuffer.push(t) → extractRenderable
          │                 → render部分编译渲染(v-html), hold暂存
          ├─ onToolCall  → toolCards.push({callId, tool, status:'running'})
          ├─ onToolResult→ 命中callId → status:'done'
          ├─ onError     → 消息标FAILED + 提示(转人工/稍后再试)
          └─ onDone      → streaming=false, StreamBuffer.flush()
                            → 完整markdown渲染(链接高亮)
                            → 回填messageId, 刷新会话列表
用户看到 "1. 星耀 X5 Pro(高亮)" → 点击
  → linkClick 委托捕获 → router.push('/products/1001')
  → 商品详情页加载(不存在的id → 路由守卫 → /404 兜底)
```

### 6.2 商品购买流程

```
商品详情 → [立即购买] → ReceiverForm 弹窗(表单校验)
  → orderStore.create({productId, quantity, receiver...})
  → 成功 → 跳转 /orders/:id (待支付)
  → [模拟支付] → status=PAID → 提示"支付成功，等待发货"
  失败: 2006库存不足 → 提示并刷新商品; 2005已下架 → 返回列表
```

### 6.3 知识库上传全流程（管理员）

```
UploadDialog 选择文件+产品+类型
→ POST /api/v1/admin/kb/docs (multipart)
→ 表格插入行 status=PENDING
→ usePolling 每3s轮询: PENDING/PROCESSING→继续; ACTIVE→停止+success; FAILED→红标+[重试]
```
