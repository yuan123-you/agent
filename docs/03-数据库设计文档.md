# 文档3：数据库设计文档

> 项目名称：AI Mall 智能电商平台（内含 AI Agent）
> 数据库：MySQL 8.0+（utf8mb4 / InnoDB）
> 文档版本：v2.0
> 最后更新：2026-08-20
> 文档状态：待评审
> 变更说明：v2.0 适配电商业务，表结构由 16 张精简为 8 张核心表；移除租户/工单/SLA/质检/通知/调用日志表；新增商品（价格库存）与订单明细表；用户表固定 3 角色（取消 MANAGER）。

---

## 1. 设计总则

1. **唯一写入方**：仅 SpringBoot 后端通过 MyBatis-Plus 写入 MySQL；Python AI 服务永不直连业务库。
2. **单平台运营**：不做多租户，所有表无 tenant_id（v1.0 的租户体系已裁剪）。
3. **主键策略**：`id BIGINT AUTO_INCREMENT`。
4. **通用字段**：`created_at`、`updated_at`（DATETIME(3)，自动填充）；逻辑删除 `deleted`（0/1）。
5. **时间口径**：应用 Clock、MyBatis-Plus 自动填充与管理看板使用 `Asia/Shanghai`；Docker 中 backend JVM 和 MySQL 默认时区同步为该口径，数据库默认时间与应用写入保持一致。
5. **软删除**：用户、商品、知识文档、会话逻辑删除；订单、消息不删除（交易与沟通凭证）。
6. **枚举存储**：VARCHAR 存枚举字符串（可读性强，便于排查）。
7. **命名规范**：表/字段 snake_case；`sys_` 系统表、`kb_` 知识库表、业务表无前缀。

---

## 2. ER 关系图（文字描述）

```
sys_user 1 ──── N conversation      （用户多个会话）
conversation 1 ─ N message          （会话多条消息）
sys_user 1 ──── N order_info        （用户多个订单）
order_info 1 ── N order_item        （订单多个明细行）
order_item N ── 1 product           （明细关联商品）
product 1 ───── N kb_doc            （商品挂多份知识文档）
kb_doc 1 ────── N kb_chunk          （文档切多分块，向量在 Milvus）
sys_user(agent) 1 ─ N conversation  （客服接管多个会话，agent_id）
```

核心主链：**用户 → 会话 → 消息**（AI 对话）与 **用户 → 订单 → 订单明细 → 商品**（交易），两链在「AI 对话中推荐商品、AI 下单创建订单」处打通。

## 4. 表关系说明

| 主表 | 从表 | 关系 | 说明 |
|------|------|------|------|
| sys_user | conversation | 1:N | user_id；agent_id 自关联（客服接管） |
| conversation | message | 1:N | 消息追加只写 |
| sys_user | order_info | 1:N | 行级归属校验（只能查自己的订单） |
| order_info | order_item | 1:N | 同事务写入 |
| order_item | product | N:1 | 价格/名称下单时快照 |
| product | kb_doc | 1:N | 商品专属知识；product_id 为 NULL 表示平台通用文档 |
| kb_doc | kb_chunk | 1:N | chunk.id ↔ Milvus 主键 |

全库**逻辑外键**（应用层保证一致性），避免物理外键锁竞争。

## 5. 数据流转与一致性策略

### 5.1 消息写入链路（强一致）

```
用户消息：后端收到请求 → 事务内插入 message(USER) + conversation.message_count+1
AI 消息：  SSE done 事件到达 → 事务内插入 message(AI, content 含链接原文 + tool_calls JSON)
回滚策略：AI 失败 → 插入 message(AI, status='FAILED') 占位，前端显示"生成失败可重试"
```

### 5.2 MySQL ↔ Milvus 双写一致性（最终一致）

```
文档摄取（正向）：
后端插入 kb_doc(status=PENDING) → 调 AI 服务摄取
  → AI：Milvus insert 向量 → 回调后端批量写 kb_chunk
  → 后端事务：插 kb_chunk + kb_doc 置 ACTIVE(chunk_count=n)
失败补偿：任一步失败 → kb_doc 置 FAILED；Milvus 幂等主键=chunk.id 重复 insert 覆盖
停用/启用：status 切换 → 检索过滤 doc_status（AI 服务检索时带标量条件）
删除：kb_doc.deleted=1 → AI 服务按 doc_id 删 Milvus 向量
重建索引：version+1 → 新向量写入 → 校验后删旧 version 向量
对账（每日定时）：比对 kb_chunk 与 Milvus count，差异告警
```

### 5.3 订单状态机与库存一致性（强一致，事务+行锁）

```
状态机：PENDING_PAYMENT →(支付)→ PAID →(发货)→ SHIPPED →(送达)→ DELIVERED
        PENDING_PAYMENT →(取消)→ CANCELLED（仅待支付可取消）

下单（页面或 AI 工具）：
  事务 { SELECT product ... FOR UPDATE（校验上架+库存）
         → 扣减 stock → 插 order_info + order_item }
  → 幂等：AI 下单以 conversation_id+消息 为幂等键，重复回调不重复下单
取消：事务 { 订单置 CANCELLED → 回补 stock }
状态流转由后端 Service 层统一校验，非法流转抛业务异常（如已支付不可取消）
```

### 5.4 冗余字段一致性

conversation.message_count 与主表同事务更新；商品快照（order_item）写后不变。

## 6. 完整建表 SQL 脚本

```sql
-- ============================================================
-- AI Mall 智能电商平台 数据库初始化脚本
-- MySQL 8.0+ / utf8mb4 / InnoDB
-- 版本: v2.0  日期: 2026-08-20
-- ============================================================

CREATE DATABASE IF NOT EXISTS ai_mall
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
USE ai_mall;

-- ---------- 用户（角色：ADMIN/AGENT/CUSTOMER，无 MANAGER） ----------
CREATE TABLE sys_user (
  id            BIGINT       NOT NULL AUTO_INCREMENT COMMENT '用户ID',
  username      VARCHAR(32)  NOT NULL COMMENT '登录名',
  password      VARCHAR(100) NOT NULL COMMENT 'BCrypt密码',
  nickname      VARCHAR(32)  NOT NULL COMMENT '昵称',
  phone         VARCHAR(20)  NULL,
  email         VARCHAR(64)  NULL,
  role          VARCHAR(16)  NOT NULL DEFAULT 'CUSTOMER' COMMENT 'ADMIN/AGENT/CUSTOMER',
  status        VARCHAR(16)  NOT NULL DEFAULT 'ACTIVE' COMMENT 'ACTIVE/DISABLED',
  last_login_at DATETIME     NULL,
  created_at    DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at    DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  deleted       TINYINT      NOT NULL DEFAULT 0,
  PRIMARY KEY (id),
  UNIQUE KEY uk_username (username),
  KEY idx_role (role)
) ENGINE=InnoDB COMMENT='用户表';

-- ---------- 商品 ----------
CREATE TABLE product (
  id             BIGINT        NOT NULL AUTO_INCREMENT COMMENT '商品ID',
  name           VARCHAR(128)  NOT NULL COMMENT '商品名',
  category       VARCHAR(32)   NOT NULL COMMENT '类目',
  brand          VARCHAR(32)   NOT NULL COMMENT '品牌',
  price          DECIMAL(10,2) NOT NULL COMMENT '售价',
  stock          INT           NOT NULL DEFAULT 0 COMMENT '库存',
  image_url      VARCHAR(255)  NULL COMMENT '主图URL',
  description    TEXT          NULL COMMENT '商品介绍',
  selling_points VARCHAR(512)  NULL COMMENT '卖点摘要',
  specs          JSON          NULL COMMENT '参数JSON',
  status         VARCHAR(16)   NOT NULL DEFAULT 'ON_SALE' COMMENT 'ON_SALE/OFF_SHELF',
  created_at     DATETIME(3)   NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at     DATETIME(3)   NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  deleted        TINYINT       NOT NULL DEFAULT 0,
  PRIMARY KEY (id),
  KEY idx_category_status (category, status),
  KEY idx_price (price),
  KEY idx_brand (brand)
) ENGINE=InnoDB COMMENT='商品表';

-- ---------- 知识库文档 ----------
CREATE TABLE kb_doc (
  id          BIGINT       NOT NULL AUTO_INCREMENT,
  product_id  BIGINT       NULL COMMENT '关联商品(NULL=平台通用)',
  title       VARCHAR(128) NOT NULL,
  doc_type    VARCHAR(16)  NOT NULL COMMENT 'FAQ/INTRO/POLICY',
  file_url    VARCHAR(255) NOT NULL,
  file_format VARCHAR(16)  NOT NULL COMMENT 'PDF/MD/TXT',
  status      VARCHAR(16)  NOT NULL DEFAULT 'PENDING' COMMENT 'PENDING/PROCESSING/ACTIVE/DISABLED/FAILED',
  chunk_count INT          NOT NULL DEFAULT 0,
  fail_reason VARCHAR(255) NULL,
  version     INT          NOT NULL DEFAULT 1,
  created_by  BIGINT       NOT NULL,
  created_at  DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at  DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  deleted     TINYINT      NOT NULL DEFAULT 0,
  PRIMARY KEY (id),
  KEY idx_product (product_id),
  KEY idx_status (status)
) ENGINE=InnoDB COMMENT='知识库文档表';

-- ---------- 知识分块（Milvus元数据镜像） ----------
CREATE TABLE kb_chunk (
  id          BIGINT      NOT NULL AUTO_INCREMENT COMMENT '与Milvus主键一致',
  doc_id      BIGINT      NOT NULL,
  product_id  BIGINT      NULL COMMENT '检索过滤',
  doc_type    VARCHAR(16) NOT NULL,
  doc_version INT         NOT NULL,
  chunk_index INT         NOT NULL,
  content     TEXT        NOT NULL,
  token_count INT         NOT NULL,
  created_at  DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  KEY idx_doc (doc_id),
  KEY idx_product (product_id)
) ENGINE=InnoDB COMMENT='知识分块元数据表';

-- ---------- 会话 ----------
CREATE TABLE conversation (
  id            BIGINT      NOT NULL AUTO_INCREMENT,
  conv_no       VARCHAR(32) NOT NULL,
  user_id       BIGINT      NOT NULL COMMENT '买家',
  agent_id      BIGINT      NULL COMMENT '接管客服',
  title         VARCHAR(64) NULL,
  summary       TEXT        NULL COMMENT '会话摘要',
  status        VARCHAR(16) NOT NULL DEFAULT 'ACTIVE' COMMENT 'ACTIVE/PENDING_HUMAN/SERVICING/CLOSED',
  satisfaction  TINYINT     NULL COMMENT '1~5',
  message_count INT         NOT NULL DEFAULT 0,
  created_at    DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at    DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  deleted       TINYINT     NOT NULL DEFAULT 0,
  PRIMARY KEY (id),
  UNIQUE KEY uk_conv_no (conv_no),
  KEY idx_user (user_id, updated_at),
  KEY idx_status_agent (status, agent_id)
) ENGINE=InnoDB COMMENT='会话表';

-- ---------- 消息 ----------
CREATE TABLE message (
  id              BIGINT       NOT NULL AUTO_INCREMENT,
  conversation_id BIGINT       NOT NULL,
  role            VARCHAR(16)  NOT NULL COMMENT 'USER/AI/AGENT/SYSTEM',
  content         TEXT         NOT NULL COMMENT '正文(含mall://链接原文)',
  tool_calls      JSON         NULL COMMENT '[{tool,args,result,elapsed_ms}]',
  token_usage     JSON         NULL,
  image_url       VARCHAR(255) NULL,
  latency_ms      INT          NULL,
  status          VARCHAR(16)  NOT NULL DEFAULT 'SUCCESS' COMMENT 'SUCCESS/FAILED/DEGRADED',
  created_at      DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  KEY idx_conv (conversation_id, id),
  KEY idx_created (created_at)
) ENGINE=InnoDB COMMENT='消息表';

-- ---------- 订单 ----------
CREATE TABLE order_info (
  id               BIGINT        NOT NULL AUTO_INCREMENT,
  order_no         VARCHAR(32)   NOT NULL,
  user_id          BIGINT        NOT NULL,
  total_amount     DECIMAL(10,2) NOT NULL,
  status           VARCHAR(16)   NOT NULL DEFAULT 'PENDING_PAYMENT' COMMENT 'PENDING_PAYMENT/PAID/SHIPPED/DELIVERED/CANCELLED',
  receiver_name    VARCHAR(32)   NOT NULL,
  receiver_phone   VARCHAR(20)   NOT NULL,
  receiver_address VARCHAR(255)  NOT NULL,
  logistics_no     VARCHAR(64)   NULL,
  source           VARCHAR(16)   NOT NULL DEFAULT 'USER' COMMENT 'USER/AI',
  conversation_id  BIGINT        NULL COMMENT 'AI下单来源会话',
  paid_at          DATETIME      NULL,
  shipped_at       DATETIME      NULL,
  delivered_at     DATETIME      NULL,
  created_at       DATETIME(3)   NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at       DATETIME(3)   NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  UNIQUE KEY uk_order_no (order_no),
  KEY idx_user (user_id, created_at),
  KEY idx_status (status)
) ENGINE=InnoDB COMMENT='订单表';

-- ---------- 订单明细 ----------
CREATE TABLE order_item (
  id            BIGINT        NOT NULL AUTO_INCREMENT,
  order_id      BIGINT        NOT NULL,
```
