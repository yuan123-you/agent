# AI Mall 支付、退款与到账规则

> 本文是 AI Mall 面向用户、商家、客服与运营人员的正式业务知识文档。具体商品或订单另有明确说明时，以用户下单时可见的商品详情、订单快照和活动规则为准；法律法规提供更高保护的，从其规定。

## 文档控制与使用说明

- **业务主题：** 支付与退款
- **文档类型：** FAQ
- **适用渠道：** AI 客服、人工客服、订单售后页面、商家工作台与平台运营后台。
- **维护原则：** 规则变更必须记录生效时间、适用订单范围和批准人；历史订单应能追溯到下单时有效版本。
- **使用边界：** 本文用于解释规则和规范操作，不替代监管机关、司法机关、支付机构、承运商或品牌授权机构依法作出的结论。

一线人员应先识别用户真实诉求，再定位适用章节。不得只复制单条结论而省略条件、例外和办理路径；无法从系统确认的事实应标记为“待核验”，不得写成已经确认。涉及资金、账户限制、隐私请求、人身安全或重大舆情时，应按升级机制转人工处理。

## 适用范围

适用于订单付款状态确认、重复支付、支付失败、订单取消退款和售后退款到账查询。

本指南同时适用于咨询、申请、审核、执行、通知、申诉和运营复盘。对于同一订单包含多个商品、多个履约包裹或多个责任主体的情况，应按最小可处理单元拆分记录，同时保留各子事项与原订单的关联。

## 核心规则

**规则 1：执行口径**

订单是否支付成功以订单详情状态和平台支付记录为准；仅有银行扣款通知但订单仍待支付时，不要连续重复付款。

执行该规则时，客服先核对适用主体、订单状态、发生时间和页面承诺，再区分系统可自动判断的事实与需要人工审核的事实。如果商品详情、活动页面或订单快照存在更具体的约定，应把页面版本和展示时间写入工单；无法确认时不得凭经验扩大或缩小用户权利。对于同一订单的多项诉求，先拆分为可独立处理的子问题，再明确每项问题的责任方、材料、期限和结果，避免用其中一项结论替代全部结论。

## 标准办理步骤

1. 支付失败时刷新订单详情，确认订单是否仍为待支付。
2. 出现扣款但订单未更新，保存扣款记录并联系人工客服，避免再次支付。
3. 退款提交后在订单的退款记录查看金额、原路退回渠道和处理状态。
4. 到账超出页面预计时间时，携带退款单号联系支付机构或平台客服核查。

完成每一步后都要把操作时间、执行人、输入材料、系统返回和下一动作写入同一工单。系统操作失败时保留错误提示和重试结果；不得通过站外私人账号绕过正式流程。用户撤回申请、订单状态变化或出现新的风险信号时，应停止不再适用的动作并重新确认方案。

## 状态管理与流转条件

**待支付**

进入“待支付”时，经办人至少记录状态开始时间、触发事件、责任主体、下一动作和预计检查点。状态连续两个检查周期没有进展时转交支付客服复核；因用户待补材料而暂停的，应明确缺少的材料、可接受的替代材料以及未补充可能产生的流程影响。
**支付处理中**

## 时限与责任

- 平台审核和发起退款的时限以售后页面展示为准。
- 支付机构入账速度不同，银行卡、钱包等渠道的实际到账时间可能存在差异。
- 商家责任导致的全额退款退还用户实付金额；个人原因退货产生的寄回运费由用户承担。

时限从页面或规则明确的起算事件开始计算。客服不得自行承诺固定到账、到货、检测或审批日期；可以提供系统预计时间，并明确影响因素。属于商家、物流、支付渠道或其他外部主体处理的事项，平台仍应提供可查询的进度和升级入口。

## 例外与注意事项

- 组合支付、优惠券或积分抵扣订单的各支付部分，按原使用方式退回或恢复，具体以退款详情为准。
- 支付渠道关闭或原账户异常时，不自行提供其他收款账户，应由人工客服按安全流程处理。

例外不是拒绝受理的同义词。发现例外时仍需完成事实登记、风险判断和必要的保护动作，再说明适用的替代路径。任何超出标准规则的特殊方案都应取得授权并记录原因、范围、有效期及批准人。

## 风险控制与合规要求

1. 只处理完成当前业务所必需的信息，不在工单记录无关身份证件、银行卡完整号码或私人聊天内容。
2. 涉及规则例外、人工补偿、账户限制或责任认定时执行双人复核，并记录授权来源。
3. 不引导用户点击陌生链接、扫描私人二维码、安装远程控制软件或提供验证码。
4. 对疑似批量、关联账号、异常频率或材料篡改的情况，先保护正常用户权益，再提交风险核验，不直接向用户披露内部策略阈值。
5. 文档、页面和客服口径不一致时，暂停引用过期口径，按对用户已展示的有效承诺处理并反馈知识维护人。

## 业务案例

**案例 1：扣款未成单**

用户就扣款未成单发起咨询。客服先从订单或账号记录确认支付渠道，并把用户陈述与系统状态支付处理中分开记录。随后依据“演示环境使用模拟支付，点击去支付后订单状态实时更新；真实支付渠道以收银台展示为准。”核对适用条件，收集“银行或钱包扣款记录、平台支付状态截图。”，交由财务对账人员完成必要复核。若复核支持用户诉求，则按页面可执行方案推进并跟踪结果；若不支持，则说明不满足的条件、现有证据与可补充路径。结案前再次检查相关商品、资金、权益或账号状态是否一致。该案例的关键不是预设支持或拒绝，而是确保适用规则、事实证据、责任判断和执行结果能够相互印证。
